# 我的 Git 学习笔记
## 第一次 Git 实验总结

通过本次实验，我结合第三章《开源软件版本控制管理》的理论知识，在本地完成了基础的 Git 操作，并初次体验了通过分支和 PR 进行远程协作的流程。看着 PPT 里提到的“手工管理版本”那种 `v1`、`v2`、`最终版`、`绝对不改版` 的混乱场景，我深刻感受到了 Git 这种分布式版本控制系统的强大与优雅。以下是我对核心操作的理解：

1. **git add 的作用是**：将工作区（Working Directory）中修改的文件添加到暂存区（Staging Area），为下一次提交做准备。PPT里提到暂存区是一个中间缓存区域，它解决了原子提交的问题。实际体验后我发现，它是选择性提交修改的关键步骤。

2. **git commit 的作用是**：将暂存区的内容保存到本地版本库（Repository），生成一次带有唯一 SHA-1 哈希值的版本快照。通过 `git log` 可以看到这些历史记录。PPT里强调Git是基于快照流存储的，这让我理解了为什么每一次 commit 都能完整记录项目状态，从而可以随时回溯。

3. **git restore notes.md 的作用是**：撤销工作区中对 `notes.md` 文件的修改，或者恢复被误删除的文件。实验中我故意追加了一句准备放弃的练习文字并使用 `git restore` 撤销，体验了它强大的“后悔药”功能，这比手工备份方便太多了。

4. **commit 与 push 的区别是**：
   - `commit` 是将修改提交到**本地**的 Git 版本库，形成本地历史链。即使断网也可以进行操作。
   - `push` 是将本地仓库的提交**推送**到**远程**仓库（如 GitHub）。只有 push 之后，团队其他成员才能通过 `git pull` 或 `git fetch` 看到这些修改。PPT中也强调了 push 是本地与远程仓库交互的核心命令。

5. **关于工作流程的体会**：结合PPT中“三区工作流”和“分支机制”的理论，我这次实验还使用了 `git switch -c homework/Yes-ysh` 创建自己的个人分支。这不仅符合开放式协作中“每人只能修改自己文件”的规则，也让我明白了分支的本质其实就是一个指向最新提交对象的可变指针。后续我会继续掌握好 `pull` 和 `merge`，真正掌握开源协作的闭环。
